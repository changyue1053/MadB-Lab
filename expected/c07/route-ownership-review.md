## Evidence and limits

The inventory preserves exact `{path, sha256, size}` original sources, their patch/baseline files, strict composed results, native generated headers and native compile units for six existing route/variant combinations. At verification time the Lab reads only its own review record and public candidate members. It does not import the producer repository, execute its helpers or inspect a developer cache.

Current candidates do not carry original sources and patches. Consequently the Lab aligns their frozen source references with independently reviewed source hashes. **It does not independently replay a patch from candidate bytes.** The review preparation used the frozen C3 composition outputs and the existing producer's restricted Rust raw bridge renderer to expose derived bytes for human review; those author-time outputs are not an independent generation oracle or a target result. The reviewer must examine both originals and the resulting composed files, including the Rust raw API/seam. Changing only a lock/composition/dependency receipt cannot change the admitted review hashes.

For C/Cpp the actual Clang command, complete fixed semantic flags, per-unit compiler dependency refs, all object output receipts, exact object list consumed by the native link, gateway factory and final native/HAR bytes must align. Test provider and Core must compile their exact reviewed derived paths; ordinary variants retain ordinary provider/Core source paths. Both original and derived closures remain present. Unknown extra frozen compiler inputs, injected `-D`/`-include` semantics, duplicate unit commands and missing source dependencies block the source review.

The inventory also binds the original provider ABI/port, worker, Core, gateway runtime/API and test memory helper/header. Dynamic identity headers are checked as a complete finite declaration; arbitrary code beside a valid factory does not pass. Other generated native headers have fixed reviewed bytes. Intermediate `.o` and Rust archive bytes are not shipped: their hashes remain build receipts rather than independent binary replay.

For Rust, the provider is the actual `#[path = "../../arkts-provider/src/lib.rs"] mod provider` in the reviewed bridge. Its original source is bound through the actual macro author's input refs, the selected test-support cfg in both actual Cargo and ohrs commands, resolved bridge/napi features, and the same actual macro/frontend evidence in declaration/link/symbol receipts. The native bridge and runtime_ffi source/object/archive/link chains are also checked. Published Rust evidence currently has no Rust source depfile; this distinction is reported explicitly. Raw frontend metadata must remain separate from typed ArkTS authority and gateway dynamic N-API counters. The pinned five napi-ohos source refs are a fixed frontend source inventory, not a generic reachability proof or proof of target execution.

## Controller use

`verify_route_ownership(candidate)` retains `status=bound` for the old public source/tool/object/link consistency check. It now also returns `original_provider_source` and `source_review`. The latter is `bound` only for a reviewed record at the exact producer revision, including all finite input/compile/link requirements; otherwise it is `blocked` with a reason. All source-review errors are fail-closed.

The controller must create its own `{candidate_digest, run_id, observation}` envelope. Both groups require the source-review result to be bound for this same candidate/route and run **in addition to every existing target scenario passing**. A source review cannot substitute for computation/free, child baseline or physical live cleanup-thread observations. Missing source review, wrong revision, failed target scenario or non-current run must remain blocked/failed/error as appropriate. Final ordinary and companion candidates must be rebuilt and rechecked; this review does not admit old development candidates.
