# MadB 整洁代码规范

目标是让维护者从局部代码看懂意图、依赖、失败方式与资源责任。规范采用整洁代码的命名、职责、抽象层次和错误处理思想，并针对 FFI、生成器与异步代码补充可检查约束。

## 命名与抽象层次

名称表达业务阶段和责任，例如 requestStop、awaitStopped、releaseBuffer、validateContract。避免用 done/ok/success 混淆“已入队、已受理、工作完成、结果交付”。

函数围绕一个可以描述的意图组织；编排函数列出阶段，细节下沉到明确职责。长度用于发现异常复杂度，不设任意统一行数作为正确性证明。禁止为了短函数把一个不变量拆散到读者无法追踪的位置。

## 数据与接口

使用能表达有效状态的类型：Closed 与 Closing 区分、明确单位和 ID、对外返回 typed error。大量相互约束的布尔字段改为带数据状态；不把所有平台信息塞进无结构 Map/Any。

公共 API 明确空值、默认值、所有权、线程与失败。构造后有效；需要分阶段初始化时暴露状态或 factory，避免创建一个只能稍后“补齐”的普通对象。

## 副作用与依赖

核心规则不读环境变量、不启动进程、不获取当前时间。需要的快照、时钟、工作区和执行器由调用方传入。应用组合根装配实现，禁止模块通过全局服务定位器寻找依赖。

`Utils`、`Manager` 等泛化容器应按真实职责拆分。共享帮助函数进入具有领域含义的小模块；平台特有函数留在对应适配器。

## 错误与资源

错误就近补充上下文，保留 cause 和稳定类别；日志放在责任边界，避免每层重复输出同一错误。不捕获所有异常后返回成功、空 DTO 或默认句柄。

获取资源之后立即建立释放责任。正常返回、错误、取消、启动失败、投递失败都必须能追踪到回收路径。RAII 管理同步资源；需要排水的异步关闭使用显式协议，析构只承担可保证的最后保护。

```rust
// 设计示意：只做判断，不在规则函数里执行编译器。
fn validate_buffer(policy: &BufferPolicy) -> Result<(), ContractError> {
    if policy.is_async_borrow() && !policy.has_keep_alive() {
        return Err(ContractError::MissingKeepAlive);
    }
    Ok(())
}
```

这类函数可直接覆盖合法、非法和边界输入。FFI 调用留在经过评审的适配模块中，注释解释其安全前提及前提由谁建立。

## 并发代码

锁保护的数据、不变量和锁顺序写在资源定义附近。避免持锁调用外部代码。检查和操作需要原子性时放在同一协议下，而不是先 `isClosed` 再使用句柄。

任务、订阅和回调必须有生命周期归属。禁止以全局后台任务掩盖收尾责任；不得通过吞取消让 UI 看起来成功。取消后的资源结果仍要有接收者或释放者。

异常处理范围与责任阶段一致：不能用一个 try/catch 同时包住业务执行和成功终态通知，再在 catch 中发送失败终态。结果通知失败进入独立诊断/清理路径，终态认领与释放仍只发生一次。相关回归应覆盖生成后的真实调用代码，不只检查模板文本。

## 注释与文档

注释解释原因、前提和反直觉的约束；不复述明显语句。公共接口文档描述效果、线程、所有权、错误与示例。TODO 必须有追踪项及触发条件。过期注释按缺陷处理。

## 生成代码

生成代码具有来源头、稳定格式和受管目录；不手工修改。生成器保证可读的函数分层、明确的错误分支及可定位源映射。对生成代码的 lint 豁免必须只限机械生成的目录和具体规则，不能屏蔽编译错误与安全检查。

上游生成器缺陷在适配器、固定源码提交或受管补丁中修复，记录模板摘要与回归用例；不得只修改一次生成结果。补丁版具有独立身份，重新生成和干净安装必须保留修复。

## 可执行规范

格式、导入和常见反模式通过工具检查；职责划分、语义和安全前提通过评审；复杂时序通过独立测试。不能用代码覆盖率、函数行数或 lint 全绿替代接口正确性。

## 文档与示例同样遵循职责边界

展示脚本不根据中文关键词推断工作包、问题编号或能力；这些关系由版本化数据显式提供。校验器检查关系和内容，不以节点数、代码行数或卡片数量作为架构深度指标。

伪代码也应保留关键前提。不能用 `if (!closed)` 示例替代准入协议，不能在 await 超时之后顺序执行 destroy，也不能把“已通知”写成“调用者已经接管资源”。实际可编译示例与协议伪代码分别标注。
