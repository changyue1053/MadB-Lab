# MadB 代码评审与质量门禁

检查按变更风险选择，避免以单一覆盖率或全量重跑替代有效验证。每个 PR 描述问题、最终行为、验证结果与尚未覆盖的目标。

## Agent 开发的执行约束

Agent 按[开发规范](07-agent-development.md)绑定任务、相关设计、修改范围和验收。评审核对实际差异与计划是否一致；范围内实现自主推进，契约或架构变化按现有决策流程处理。不得靠修改规则、放宽断言或跳过必需项消除失败。

按变更风险使用下列已有门禁，不新增一套 Agent 验收状态。局部交付与整工作包完成分开，未执行项明确保留。根 AGENTS.md、检查入口与实际合入约束由 C01 落地；本文不会自动创建 CI 或仓库权限配置。

## 评审清单

| 变更 | 必查内容 | 所需证据 |
|---|---|---|
| 公共 API/契约 | 类型、线程、所有权、取消、兼容与文档 | API 比较、正反例、消费端编译 |
| 核心模型/规则 | 单一职责、纯函数、精度与缺口区分 | 单元测试、结构校验、确定性 |
| 生成器 | 来源追踪、路径所有权、失败恢复、可读性 | golden、重生成、编译和语义测试 |
| 注解/宏/便利 API | 普通入口可用、无隐藏副作用、语义与来源一致、编译依赖明确 | [DX 验收](https://github.com/changyue1053/MadB/blob/bd2fc28dca8e72995ee9bce6330c6b37ad8b557d/docs/validation/07-developer-ergonomics.md)、宏组合与独立消费 |
| 运行时 | 状态机、别名、释放器、重入与终态认领 | 定时序交错、资源计数、适用动态检查 |
| 诊断/插桩 | 可选采集与必要保护分离、有界开销、无重复计数 | 开关对照、sink 失败注入、未插桩 Release |
| 后端/工具链 | 运行时、方向、交付形态、构建系统、稳定发布与模板补丁身份 | 精确锁、目标编译与运行、实际公开接口调用、反向调用 |
| 语言/运行时扩展 | 开放身份、受检语义、协议协商、组件依赖与禁用隔离 | [扩展验收](https://github.com/changyue1053/MadB/blob/bd2fc28dca8e72995ee9bce6330c6b37ad8b557d/docs/validation/05-language-onboarding.md)及真实消费探针 |
| 打包/发布 | 文件完整性、许可、符号、装载、根 metadata、native 依赖与分发设置 | 干净环境从候选包消费；官方/CPF 坐标无冲突，Apple 制品异机可用 |
| 文档/示例 | 可运行、链接有效、无误导能力声明 | 文档检查和相关示例 |

## 自动门禁层次

1. 快速检查：格式、静态规则、文档链接、catalog 引用、依赖方向。
2. 模块检查：单元测试、规范正反例、生成漂移与失败恢复。
3. 受影响路线：按依赖图选择编译和消费者测试；无法可靠计算影响时扩大范围。
4. 发布检查：全部声明支持的配置、必需问题组、Release/设备要求、许可和包完整性。

测试超时和环境错误不能转换为 skipped 后放行。负例需要声明期待的诊断/失败，不能把任意崩溃当成功。修改 expected 数据须说明契约变更原因，避免为了消除测试失败而更新黄金文件。

后端升级同时检查其生成模板和运行依赖；模板仍含旧缺陷时不能仅凭 runtime 版本放行。成功终态通知抛异常的重复完成回归、SKIE unavailable 接口调用、缺设备仅构建的 smoke 结果，分别按其真实能力与执行层级判定。

新增语言改变 model/rules/plan 时，必须说明缺失的公共语义、协议兼容和受影响路线；仅为调用某语言工具而修改核心属于边界问题。扩展清单结构有效不代表组件引用、能力、权限或运行状态已通过验证。

## 人工审查重点

unsafe、线程能力、结果所有权转移、关闭排水、动态装载和复杂原生异常边界需要对应语言经验的审查者。关注真实不变量与证据，不要求机械增加特定模式、类数或抽象层。

小型无行为变更可只跑受影响检查；公开行为、安全前提或工具链变化需扩大验证。格式化不能夹带无关重构，修复也不以改写整个模块为默认选择。

## 门禁与例外

原型评审检查假设、范围和失败预期，不要求预先冻结全部语言 API。正式集成按[设计准入](https://github.com/changyue1053/MadB/blob/bd2fc28dca8e72995ee9bce6330c6b37ad8b557d/docs/delivery/04-design-readiness-and-first-route.md)核对契约、生成形状、依赖和可执行样例；公开发布再核对公共声明与兼容承诺。自定义便利层必须有等价普通用法及 DX 证据，架构表中列出技术名称不能替代这些材料。

候选发布的必需证据缺失必须阻断。实验性能力可以明确不在认证集合中继续开发，但不能以“已知问题”将失败伪装为通过。临时 CI 故障记录复现信息并重新执行，证据仍绑定原候选内容。

评审结论和门禁记录保存于代码托管系统或版本化报告；政策由本文维护，具体 CI 配置在实现时落地。

## 文档和 HTML 专项门禁

规范、计划、展示数据、模板和生成 HTML 作为一个变更审查，使用[文档质量规范](https://github.com/changyue1053/MadB/blob/bd2fc28dca8e72995ee9bce6330c6b37ad8b557d/docs/engineering/06-documentation-quality.md)。必须检查路线独有机制、条件与拒绝路径、原生/队列/消费者三段生命周期，以及问题→任务→验收的显式映射。节点数量、链接可用和 JS 语法通过仅是结构证据。

`python3 tools/check_docs.py` 运行静态一致性检查，`python3 -m unittest discover -s tools/tests` 验证文档工具的关键拒绝规则。浏览器渲染、窄屏、键盘和交互结果另记录，未执行不能写成“已通过”。

## 实施契约的评审准入

按[设计决定](https://github.com/changyue1053/MadB/blob/bd2fc28dca8e72995ee9bce6330c6b37ad8b557d/docs/adr/0009-implementation-contracts-and-gates.md)检查四类资产：明确规则、实际接口/schema/任务图、成功用例、准确负例。首链集成先通过 DEC-01 至 DEC-06 及所用运行机制；后续 profile 再落实责任表、调度/容量、装配和制品匹配。规则已经写入文档不等于实现通过。

并发生成与增量输入使用 CRIT-09/10；资源句柄和执行器退出使用 CRIT-08/11；身份与错库使用 CRIT-07/12。已有门禁和案例继续保留，决策索引不增加第二套进度统计。

## C01 检查环境与远程约束

项目固定 Rust、Python 和 Node 的使用版本，校验库及传递依赖有锁定清单；README 给出从独立检出建立环境和运行检查的完整步骤。依赖缺失应失败并说明未执行项，不从作者机器临时目录补入依赖或依赖一次性的全局 pip 安装。

C01 至少验证：默认与 all-features 构建；解析后的生产/构建依赖，包括目标条件及依赖别名；一个真正触发规则的反向依赖负例；Lab 无工具私有源码仍可运行自身检查。声明的其他目标组合随实际成员/配置加入，不从宿主检查推导平台认证。

CI 使用同一检查入口，外部 PR 不接收发布凭证。远程仓库的必需检查与合入限制须实际配置并验证；本地检查、工作流 YAML 或待创建仓库不能替代这一结果。门禁暂未具备时保留 C01 未完成项，不削弱验收。

## 工程骨架的依赖门禁

目录与允许依赖以[模块规范](https://github.com/changyue1053/MadB/blob/bd2fc28dca8e72995ee9bce6330c6b37ad8b557d/docs/architecture/02-modules-and-ports.md)为准，Lab 结构以[验证工程](../validation/02-lab-architecture.md)为准。C01 建立检查入口，C04 随实际实现收紧边界；规则的预期失败也必须可复现，不能只展示当前没有违规。

| 检查 | 必需正例与负例 | 落点 |
|---|---|---|
| 核心依赖 | model/rules/plan 不依赖 app、protocol、适配器或 SDK；注入一条反向依赖应失败 | tests/architecture；C01、C04 |
| 端口与装配 | app 仅使用端口；bootstrap 绑定实现；将具体后端导入 app 应失败 | 应用公开接口与模块可见性；C04 |
| DTO 与领域模型 | adapter 显式转换 wire/领域值；跨格式向量一致；app 不直接以 DTO 绕过领域校验 | 协议与契约检查；C02、E02 |
| 适配器和宿主权限 | 打包器只能准备候选；跨私有路径调用、越过 host 提交应被编译边界或能力检查拒绝 | 架构检查及集成负例；C04、C10 |
| SDK 与工具隔离 | 原生消费者仅依赖语言 SDK/绑定；引入 CLI 或工具宿主依赖应失败 | 各语言依赖清单和独立消费；C05、平台任务 |
| Lab 的独立性 | 候选包正常安装并运行；移除工具源码目录和开发缓存后仍可验收；私有路径依赖应失败 | 消费与分发场景；C05、C09 |
| 文件归属 | 重生成保留手写文件；扩展索引不复制实现；用户源码与输出目录冲突应明确拒绝 | 生成/初始化测试；C04、E01、I01–I03 |

Rust 依赖检查读取解析后的构建依赖并结合模块可见性检查；覆盖所声明的 target/feature 与 build-dependency，不靠目录名字或文本搜索断言隔离。其他语言使用对应构建清单和公开消费检查。测试替身只经公开接口注入，不能用 dev-dependency 将生产代码偷偷连回适配器。

这些是产品工程实施门禁；文档脚本只校验规范、映射和投影，不能替代 Cargo workspace 的实际构建和依赖检查。构建单元的新增或合并提交实际 manifest、依赖变化和隔离理由，不以空目录数量作为完成指标。
