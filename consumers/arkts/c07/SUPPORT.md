# Minimum public companion coordination

This is a requirement list, not a proposed business API or invented `.d.ts`. Method names and scalar frame indexes are deliberately unbound until the author delivers a reviewed public companion declaration and manifest. The ordinary package remains independently runnable without it.

Environment author confirmed that the new C gateway will retain actual Core tokens within the same32, reuse its before-guard/consume/after-resolver fault seams, and use a real Publication lease for acquired-before-enqueue coverage. Provider currently supports next-clone failure; a fail-after-one-success fixture must be implemented at the real provider clone owner, not faked in the gateway. Worker controls need coordination with the actual worker owner.

## Four small mechanisms

1. **Actual work hold:** one bounded one-shot phase gate around the current operation, selectable before terminal claim or after terminal claim/before work exit. Arm before ordinary `startOperation`; a native arrival sequence records phase, operation/generation, actual thread and owner. Lab awaits that read-only observation asynchronously; release is pure-native, idempotent, valid while closing, and never waits for JS. Do not park the env, fake `workActive`, or equate terminal/loop-exit/Future with physical join. Existing private host barriers may be adapted only through the published companion.
2. **Actual publication hold:** one bounded companion transaction reserves/selects the real source/fanout leases, optionally performs actual clone allocation, then waits for an explicit commit/abandon control. It must use existing business tickets/bytes and final cleanup paths. It gives acquired-before-enqueue and pre-entry state replacement checkpoints without pretending the ordinary profile has an autonomous source. Stop must close new entry while the acquired owner persists. The env never synchronously waits for itself. Actual entered callback cases use user callback reentry and need no new scheduling API.
3. **Existing narrow failures:** registration before claimant commit, transfer before consume guard, conversion after guard, and failure after accepted settlement; at most one armed occurrence per fixture. Real provider next/fail-at clone supports partial fanout rollback, including non-null error outputs. Exact typed public rejection code/stage comes from the fixed contract; an arbitrary exception is not enough. Fault count, trigger sequence and actual allocation/free sites must distinguish an armed-but-never-hit test.
4. **Read-only ownership/physical observations:** publish a fixed bounded frame plus layout identity. It should report genuine counters and phases, not `passed`, synthetic cleanup or expected values. Existing static bootstrap channel remains safe after close/env invalidation. A closed receipt is immutable and generation-checked; no dereference of freed native state, unbounded history, or reuse of a slot before its intended receipt consumer.

No public wait/cancel-timeout API, per-test thread, general scheduler, debug allocation of waiters or hidden33rd slot is requested. Native test holds may exist only within admitted capacities and must be released by normal/actual cleanup even when the test fails. Reuse ordinary requestClose/requestStop/requestCancel for all admission gates.

## Raw observations needed (concepts, not frozen names/indexes)

| Ownership interval | Minimum observations |
|---|---|
| Identity/admission | epoch + route/env/generation identity; raw phase; each actual business/ref/TSFN/worker admission total. Mismatch checks compare independently fixed expected constants before resource creation. |
| Protocol | operation and shared subscription owners; queued/running work and terminal winner per selected operation; source/staging/pending/entered phase counts; event outstanding; state pending and entered per chosen subscription; retained bytes and scratch current/peak. |
| Completion | shared Core waiters by result/close/ready/entered, facade registering/settling, parent close control count, notification queued/entered; claim commit/rollback and consumed/discarded totals. Distinguish alias indexes from another quota. |
| Route provider | actual clone success/error-output/compute/free counts and retained bytes, with returned object identity where needed to prove once-free; input/output ownership transitions. Counters are at true ownership sites, not inferred from protocol slot decrements. |
| Callback | actual callback-enter/return/throw sequence, owner thread while alive, callback/ref release, callback attempted after stop, and API call after invalid env. A user-return value is never a business acceptance ACK. |
| Worker | actual started, work-exited, loop-exited, TLS-destroyed, cleanup executor started, join returned, Executor released sequence/totals; live owner/business/cleanup thread witnesses. Historical numeric tid reuse is not proof of self-join. |
| Runtime | references created/deleted/live (include sentinel, class and metadata owners), hooks registered/removed/invoked, async cleanup entered/return marker/work complete/remove result, TSFN created/finalized, payload allocated/released, context created/destroyed, failed/uncertain cleanup. |
| Facade end | timerArmed, tickInFlight and current map/settling owners become zero only after static physical ACK. Cumulative timer ticks remain cumulative and are not expected to be zero. |

Exact reference totals may differ by route. Capture the declared stable open baseline; operation/subscription cleanup returns to it. Final Runtime close must reach true zero of retained owners and pair cumulative create/release values, including permanent-in-open-runtime sentinel/metadata refs. Do not assert all cumulative counters equal zero.

Frame semantics must say whether reads are coherent, or identify a stable phase gate/sequence. A sequence number from separate atomic fields alone does not create coherence. During a known transition, enforce only defensible inequalities and wait for a stable checkpoint. Missing fields/layout mismatch are errors, never default zeros. Raw and parsed frames are both retained.

## Exact32 schedule

Before calling `runFullWaiterScenario`, the companion has observed an actual ordinary operation held **before terminal**. In one synchronous env turn, call that operation's `result()` once, then call its `close()`31 times. Each pending child close is a separate ordinary observer and requests cancellation; they do not memoize. Because ready only marks dirty and cannot recursively consume, the stable same-turn observation must show32 accepted responsibility slots. Attach rejection handlers before yielding.

The next pending `Operation.close` rejects ResourceExhausted. Runtime.close starts its pre-reserved parent path and requests native stop; another Runtime.close shares that path. Record that the actual held work still prevents join/physical ACK. Then release the native hold, await the already-admitted Cancelled result, all31 close observers and parent close, and check static physical ACK and zero facade owners. The result can retire after yielding; do not keep expecting32 after its cancellation settlement.

The mixed type and request-before-observer variants must keep Subscription close truly pending using an acquired source or current entered callback. An idle subscription may already be Closed and legitimately return a value-only Promise; that is not a32-slot admission test. Test Engine and Subscription observer rejection in separate controlled schedules if necessary. A fresh second operation's rejected result precommit can be retried only while its engine/operation admission remains open; do not combine the retry test with an Engine close that intentionally forbids it.

## Physical shutdown and actual env exit

Normal close: request → source/work/callback drain → true native join including TLS → Core close; Core ACK observers may still exist, so Runtime waits their retirement and facade settling/notification owners → ref/hook/TSFN cleanup → finalizer/payload/context physical ACK → stop future polling → resolve parent. Observe necessary partial orders, not an arbitrary universal order between TSFN finalizer and async-handle removal.

Real env exit: parent receives a stable provider epoch; Worker records exit-request occupancy and immediately calls workerPort.close in the same stack with no await/post between. This is permitted only for routes whose profile supports that env. Actual async hook gates entry and returns without join/wait; pre-reserved cleanup executor joins; owner-loop removal follows required completion; null-env delivery frees only its legitimate native owner. Record actual occupancy again at hook entry; platform draining before the hook cannot be rewritten as a full hook-entry queue. Context ACK requires all relevant owners to have completed. For Kotlin main-env-only, ordinary complete runtime shutdown while the env is still valid is the required normal-close path: autonomous gate/drain, all references including sentinel/metadata/class owners, and actual TSFN finalizer ACK. Host-VM destruction is not an extra normal-close requirement. System-hook/null-env evidence is separately recorded as observed or unobserved and assessed only against the final declared profile responsibilities; it is neither inferred from normal close nor made an extra mandatory main-VM-destruction gate by this support plan.

Keep error/uncertain-transfer counters and raw failed removal/deletion status. Never clear ownership pointers or counters merely to make final zero. Test recovery may terminate a stuck process but then reports timeout/error and incomplete cleanup.
