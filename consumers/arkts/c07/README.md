# C07 independent ArkTS consumers

Consume only admitted public HAR candidates. The runner must bind a public module name, exact candidate/profile identity, explicit SDK/JDK paths and one explicit target. It must not import a producer checkout or developer cache. The source templates contain the independent expected values and resource obligations; diagnostics describe observations, never replace those expectations.

The ordinary and test companion are distinct candidates. `requirements.json` is this suite's input, not a new public protocol or certification status. Each route requires the union of five ordinary and twenty-five companion groups. Missing fixtures or generation-tool inputs remain blocked; scenario counts are not case coverage. The Kotlin main-env-only profile uses its own reviewed diagnostic layout, not the C156 frame.

The C/C++/Rust controlled fixtures use public companion functions and fixed numeric layout contracts. The actual producer contract attachments must be in the candidate inventory; no adjacent temporary file lookup is permitted. Normal physical shutdown and actual Worker env cleanup are separate. The supported C/C++/Rust frame has 178 fields: the original 156, twelve owner-local counters retained in physical history, and ten live process counters. Zero null-env counters mean the branch was unobserved; they do not establish coverage. Kotlin uses its own declared layout and remains unsupported by this controlled executor.

Runtime commands use bounded timeouts and one explicit hdc target. Never enumerate devices, restart the server, change HOME, silently skip a missing SDK/device, or treat process force-stop as native cleanup. Source/HAP/log/namecache archives must be per nonce; mutable scratch paths are excluded from receipts. Signing is supplied explicitly through a user-selected config or SDK public community debug materials. No signing keys or actual private configs belong here.

The source-only framework shell uses Hvigor6.26.8 and SDK26/API23 profile settings. Tool and target identity must be checked against each admitted candidate before execution. Existing development observations are not final-candidate reports.

C07 runtime identity uses `madb.arkts-runtime-identity/1`: exact ABI/profile/build digests and the corresponding bootstrap string. It is intentionally distinct from the four-field C05/C06 `madb.native-identity/1`. A six-field C07 artifact carrying the old tag is rejected, not silently upgraded.

Run `python3 scripts/verify_c07.py --candidate <public-candidate> --route c --command-line-tools <SDK-CLI-root> --java-home <JDK-home> --target <explicit-id> --target-kind emulator --community-debug-signing --output <new-empty-directory>`. Use `--signing-config <explicit-config>` instead when supplying signing configuration. `--allow-dirty` emits provisional evidence only. The ordinary runner executes ordinary/values/output-copy/distribution. The ordinary C, C++ and Rust generation cases additionally require `--generator-cli <public scripts/build_arkts_routes.py> --generation-fixtures <public author-fixture directory> --cli-inventory <acquisition inventory> --cli-inventory-sha256 <pin> --madb-image <CLI-image> --madb-sha256 <pin> --finalizer-image <finalizer-image> --finalizer-sha256 <pin>`. `--generation-only` runs those public commands without device or signing arguments; target cases remain blocked in that report. Rust also requires `--rust-configuration <public-config> --rust-configuration-sha256 <pin>`; its actual raw macro names/arity must match the typed gateway and the frontend remains napi3. Kotlin generation remains unavailable until the public KSP author fixture and its real declaration transformation are connected; an ArkTS-only rename does not satisfy that case. Generation checks real renamed declarations/ContractIR/Source members, preserved explicit capability IDs, and exact source-located rejection codes for an async export, a number-return listener, and a Promise-return listener. Both MadB images must match the admitted candidate tool identities, and each fresh generation must report the same complete compiler image set. An independently supplied hash is not a source attestation. The public CLI runs with Python isolation flags `-I -S -B -X pycache_prefix=/dev/null`. Formal attribution requires the candidate producer revision in a clean checkout before and after execution with tracked CLI/fixtures. Dirty/provisional observations remain separate evidence and keep candidate generation blocked; they never amend an earlier report. Use `--companion` for fresh serial controlled HAP consumers. Each registered group is assessed from this exact candidate and controller run; missing scenario coverage keeps that group blocked. The independent execution map lists remaining gaps and never imports prior development results. Each scenario has a unique nonce, HAP, source archive and process, with a 50-second target watchdog including installation/start. Group budgets scale with their scenario count; source build commands are separately bounded. Failed scenarios retain raw output and receive an isolated recovery stop, which does not establish native cleanup. The command returns nonzero whenever any required case is blocked or failed.

Tool inventory validation is independent: the whole CLI tree includes directory/file/symlink entries, permissions and raw per-file SHA-256; JBR uses only file/symlink entries, executable flags and prefixed per-file digests. Both compare the public compact-JSON inventory digest and reject escaping symlinks. The actual executed Hvigor file is `hvigor/hvigor/bin/hvigor.js`. Fresh task caches keep build outputs outside those verified trees. The public signing helper runs the explicitly selected Lab Python, not an incidental PATH interpreter.

The selected artifact format binds candidate identity to explicit generated facade/header constants, the actual HAR ABC identity value, and each SDK DSO identity value. Missing, malformed, conflicting or different values fail admission. This is byte consistency for the reviewed format, not proof of arbitrary machine-code semantics. The native inventory includes all declared files, dependencies and build evidence, including renamed ELF and versioned libraries. Build and device child processes inherit a narrow home/connection environment; ambient Node/Java/Python/dynamic-loader injection is excluded. No script changes HOME or restarts hdc.
