# C07 independent ArkTS consumers

Consume only admitted public HAR candidates. The runner must bind a public module name, exact candidate/profile identity, explicit SDK/JDK paths and one explicit target. It must not import a producer checkout or developer cache. The source templates contain the independent expected values and resource obligations; diagnostics describe observations, never replace those expectations.

The ordinary and test companion are distinct candidates. `requirements.json` is this suite's input, not a new public protocol or certification status. Each route requires the union of five ordinary and twenty-five companion groups. Missing fixtures or generation-tool inputs remain blocked; scenario counts are not case coverage. The Kotlin main-env-only profile uses its own reviewed diagnostic layout, not the C156 frame.

The C/C++/Rust controlled fixtures use public companion functions and fixed numeric layout contracts. The actual producer contract attachments must be in the candidate inventory; no adjacent temporary file lookup is permitted. Normal physical shutdown and actual Worker env cleanup are separate. The current old development frame has no independent illegal-NAPI-attempt counter; complete env-exit-full cannot pass from that omission.

Runtime commands use bounded timeouts and one explicit hdc target. Never enumerate devices, restart the server, change HOME, silently skip a missing SDK/device, or treat process force-stop as native cleanup. Source/HAP/log/namecache archives must be per nonce; mutable scratch paths are excluded from receipts. Signing is supplied explicitly through a user-selected config or SDK public community debug materials. No signing keys or actual private configs belong here.

The source-only framework shell uses Hvigor6.26.8 and SDK26/API23 profile settings. Tool and target identity must be checked against each admitted candidate before execution. Existing development observations are not final-candidate reports.

C07 runtime identity uses `madb.arkts-runtime-identity/1`: exact ABI/profile/build digests and the corresponding bootstrap string. It is intentionally distinct from the four-field C05/C06 `madb.native-identity/1`. A six-field C07 artifact carrying the old tag is rejected, not silently upgraded.

Run `python3 scripts/verify_c07.py --candidate <public-candidate> --route c --command-line-tools <SDK-CLI-root> --java-home <JDK-home> --target <explicit-id> --target-kind emulator --community-debug-signing --output <new-empty-directory>`. Use `--signing-config <explicit-config>` instead when supplying signing configuration. `--allow-dirty` emits provisional evidence only. The ordinary runner executes ordinary/values/output-copy/distribution. The C generation case additionally requires `--generator-cli <public scripts/build_arkts_routes.py> --generation-fixtures <public author-fixture directory> --cli-inventory <acquisition inventory> --cli-inventory-sha256 <pin>`. `--generation-only` runs those public commands without device or signing arguments; target cases remain blocked in that report. Generation checks real renamed declarations/ContractIR/Source members, preserved explicit capability IDs, and exact source-located rejection codes for an async export, a number-return listener, and a Promise-return listener. The public CLI runs with Python isolation flags `-I -S -B -X pycache_prefix=/dev/null`. Formal attribution requires the candidate producer revision in a clean checkout before and after execution with tracked CLI/fixtures. Dirty/provisional observations remain separate evidence and keep candidate generation blocked; they never amend an earlier report. Controlled templates are preserved but their final candidate runner is not yet wired; they cannot pass by referencing old development runs. The command returns nonzero whenever any required case is blocked or failed.

Tool inventory validation is independent: the whole CLI tree includes directory/file/symlink entries, permissions and raw per-file SHA-256; JBR uses only file/symlink entries, executable flags and prefixed per-file digests. Both compare the public compact-JSON inventory digest and reject escaping symlinks. The actual executed Hvigor file is `hvigor/hvigor/bin/hvigor.js`. Fresh task caches keep build outputs outside those verified trees. The public signing helper runs the explicitly selected Lab Python, not an incidental PATH interpreter.

The selected artifact format binds candidate identity to explicit generated facade/header constants, the actual HAR ABC identity value, and each SDK DSO identity value. Missing, malformed, conflicting or different values fail admission. This is byte consistency for the reviewed format, not proof of arbitrary machine-code semantics. The native inventory includes all declared files, dependencies and build evidence, including renamed ELF and versioned libraries. Build and device child processes inherit a narrow home/connection environment; ambient Node/Java/Python/dynamic-loader injection is excluded. No script changes HOME or restarts hdc.
