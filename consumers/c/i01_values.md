# I01 initial Rust-to-C value consumer

This slice consumes one clean public candidate from template 0.1.1's initial
`reading_demo` business, profile `i01-native-values-macos-arm64-0-1-1` on macOS
arm64. It uses the existing Candidate, Case and Report v1 formats. The exact
mandatory set is `i01.rust-c-values.bootstrap` and
`i01.rust-c-values.ordinary`. Missing, additional or duplicate case declarations
are rejected; this is not the seven-candidate L02 suite.

The ordinary consumer calls `reading_demo_normalize` with normal inline C model
values. Eleven independently fixed vectors cover ASCII and Unicode whitespace,
empty and all-whitespace text, embedded NUL, supplementary Unicode, 64-byte
ASCII/Unicode payloads, signed integer boundaries and non-whitespace U+200B.
Every vector checks all input bytes remain unchanged, success kind/status/error,
exact output bytes and zero unused output tail. The Lab's Python observer also
compares every value record against a separate fixed byte table; `7:x` alone
cannot satisfy the oracle. The author file under `cases/i01` binds the initial
public input bytes only and is never executed as the expected implementation.

The separate bootstrap case checks the actual loaded image and complete
interface/profile identity, capacity/null rejection and unsupported-version
output handling. Identity passed to the observer is not a business argument.
The ordinary header obtains its own expected identity from its generated bytes.

The verifier copies the complete public candidate into an isolated consumer
directory, checks public hashes/IR/profile/lock/layout before and after, binds
the actual Clang image and SDK headers to the public toolchain receipt, freezes
both case instances before consumer compilation, and saves raw argv/stdout/
stderr/timing plus source, dependency and image identities. Successful process
completion is observed by `communicate`, which reaps the child; timeout is an
error and kill is not SDK cleanup. Inline values have no consumer free/close,
and no numeric Rust allocation or author-call count is claimed.

Use the pinned Lab Python and clean producer/Lab commits:

```text
python3 -B scripts/verify_i01_values.py --candidate /absolute/public-candidate \
  --candidate-digest sha256:EXACT_DIGEST --producer-revision FULL_COMMIT \
  --lab-revision FULL_COMMIT --output /absolute/new-evidence-directory
```

The optional `--clang` selects an actual compiler image that must match the
public profile; it cannot bypass the image or SDK checks. No dirty/provisional
mode exists. A missing candidate or environment fails without a passed report.
`harness/tests/test_i01_values.py` tests the evidence rules with model fixtures;
the default repository check discovers it and does not thereby certify an SDK.

These two cases prove only the initial SDK's bootstrap and normal value call.
They do not prove `init` execution, final-project CMake/CLI operation, IDE import,
debugging, mutation/rebuild, the full L02 matrix, other platforms or publication.
